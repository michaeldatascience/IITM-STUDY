§1 · NumPy — the ten operations that are 95% of DL code

Motivation. Every model in the theory guide is, at machine level, arrays flowing through ~10 primitive operations. If these are reflexes, reading any paper's code becomes trivial; if not, every implementation session dies in shape-error archaeology. Learn the primitives cold.

The core ten 
import numpy as np
X = np.random.randn(4, 8)        # (batch/tokens T=4, features d=8), N(0,1)

# 1. matmul — THE operation. (T,d)@(d,k) -> (T,k). Inner dims must match.
Y = X @ np.random.randn(8, 3)

# 2. transpose — swap axes. K.T flips (T,d)->(d,T). For >2D: .transpose(perm)
S = X @ X.T                      # (4,4) all pairwise dot products = attention scores!

# 3. reshape — reinterpret memory, size must be conserved
H = X.reshape(4, 2, 4)           # split d=8 into 2 heads of dk=4  (T, h, dk)

# 4. axis reductions — sum/mean/max/argmax along an axis; the axis DISAPPEARS
X.sum(axis=0)                    # (8,)  column sums   ("collapse rows")
X.mean(axis=-1, keepdims=True)   # (4,1) per-row mean  <- LayerNorm uses exactly this

# 5. element-wise ops + ufuncs: X*2, X**2, np.exp, np.tanh, np.maximum(0,X)
# 6. indexing/slicing: X[0], X[:, 2:5], X[[0,2]], boolean masks X[X>0]
# 7. concatenate / stack:  np.concatenate([a,b], axis=-1)  <- multi-head concat
# 8. np.where(cond, a, b): vectorised if-else  <- masking
# 9. random: rng = np.random.default_rng(42); rng.normal(size=(d,d))
# 10. comparison/verification: np.allclose(a, b, atol=1e-6)  <- your test harness

The axis mental model (memorise this one sentence): the axis you name is the axis that gets consumed. sum(axis=0) eats the rows-axis and leaves columns. In DL convention, axis −1 is almost always the feature dimension, so "per-token statistics" = axis=-1. That single convention is the entire LayerNorm-vs-BatchNorm distinction from the theory guide, in code.

einsum — the notation that makes attention a one-liner (optional but powerful)

np.einsum names each axis with a letter; repeated letters are multiplied-and-summed. Rules: letters shared between inputs and absent from output are contracted; letters in the output are kept.

np.einsum('td,dk->tk', X, W)          # matmul
np.einsum('qd,kd->qk', Q, K)          # Q @ K.T  (scores) — note both use d, output qk
np.einsum('hqk,hkv->hqv', A, Vh)      # batched per-head attention in one call

Why bother: einsum forces you to state every tensor's axes, which is self-documenting and kills 90% of transpose bugs. PyTorch has the identical torch.einsum.

1.1 Drill — predict shapes before running

Q1. A=(3,5), B=(5,5), C=(5,2). Shape of (A@B)@C? Of A@(B@C)? Which order is cheaper?

Both give (3,2) — matmul is associative. Cost: (A@B) is 3·5·5=75 mults then 3·5·2=30 → 105. (B@C) is 5·5·2=50 then 3·5·2=30 → 80. Order changes cost, not result — the germ of the matrix-chain problem, and why frameworks care about computation graphs.

Q2. X is (T, d). Write per-row L2 normalisation in one line.
Xn = X / np.linalg.norm(X, axis=-1, keepdims=True)

keepdims=True keeps the consumed axis as size 1, i.e. (T,1), so broadcasting divides each row by its own norm. Drop it and you get (T,) which still broadcasts here but breaks the moment T = d — a silent-bug time bomb. Always keepdims.

Q3. Split X:(T,d) into h heads → (h, T, d/h) without einsum.
X.reshape(T, h, d//h).transpose(1, 0, 2)

Why not reshape(h, T, d//h) directly? Reshape preserves memory order: row t holds token t's features contiguously, and the head-split must cut within each token's features (last axis) first, then move heads out front. Direct reshape would scramble tokens across heads. This is the single most common MHA implementation bug.

§2 · Broadcasting, rigorously

Motivation. Broadcasting is how NumPy/PyTorch apply operations between arrays of different shapes without copying data. It's also the #1 source of code that runs without error and is silently wrong. You must be able to execute the algorithm in your head.

The broadcasting algorithm (this is the complete rule)
  1. Right-align the two shapes. Pad the shorter one with 1s on the left.
  2. Compare axis by axis. Compatible iff equal, or one of them is 1.
  3. Each size-1 axis is (virtually) copied to match the other. Any other mismatch → error.
(T, d)   +  (d,)    → (T,d)+(1,d) → (T,d)   # bias add: one bias per feature, every row ✓
(T, 1)   *  (1, T)  → (T, T)                # outer product
(h,T,dk) @  (h,dk,T)→ (h, T, T)             # batched matmul: leading axes broadcast, last two matmul
(T, d)   +  (T,)    → (T,d)+(1,T) → ERROR unless d==T  ← the classic silent/loud bug
Worked example — the LayerNorm bug you will write one day 
x = np.arange(12.).reshape(3, 4)     # 3 tokens, 4 features
mu_bad  = x.mean(axis=-1)            # (3,)   forgot keepdims
mu_good = x.mean(axis=-1, keepdims=True)  # (3,1)

x - mu_good     # (3,4)-(3,1) → ✓ each row minus its own mean
x - mu_bad      # (3,4)-(3,)  → right-align: (3,4) vs (1,3) → ERROR. Lucky!
# Now suppose x were (4,4):  (4,4)-(4,) broadcasts FINE — but subtracts the
# per-ROW means across COLUMNS. Runs, trains, converges worse. Silent wrongness.

Rule you now own: after any reduction that will re-combine with the source array, write keepdims=True. No exceptions.

Drill: scores:(T,T), mask −∞ above diagonal — three ways. Which broadcasts?
i = np.arange(T)[:, None]     # (T,1) row index
j = np.arange(T)[None, :]     # (1,T) col index
mask = np.where(j > i, -np.inf, 0.0)   # (T,1) vs (1,T) → broadcast to (T,T) ✓

The comparison j > i itself broadcasts to a (T,T) boolean — index-grid tricks like this build masks, PE tables, and distance matrices without loops. Alternative: np.triu(np.ones((T,T)),1). Both fine; know both.

§4 · Activation functions: math → derivative → code

Motivation. Without nonlinearities, a stack of linear layers collapses: \(W_2(W_1x) = (W_2W_1)x\) — one matrix, however deep. Activations are what buy depth its expressive power. And since backprop multiplies local derivatives along the chain, each activation's derivative shape decides whether gradients survive. Derive every one — the derivatives below are exactly what you'll hardcode into your Value class.

The catalogue, derived

Sigmoid \(\sigma(x) = \frac{1}{1+e^{-x}}\). Derivative, by chain rule on \((1+e^{-x})^{-1}\): $$\sigma'(x) = \frac{e^{-x}}{(1+e^{-x})^2} = \underbrace{\frac{1}{1+e^{-x}}}_{\sigma}\cdot\underbrace{\frac{e^{-x}}{1+e^{-x}}}_{1-\sigma} = \sigma(x)(1-\sigma(x))$$ Max value 0.25 (at x=0) → every sigmoid layer multiplies gradient by ≤ 0.25 → vanishing gradients in deep stacks. Outputs in (0,1): use for probabilities/gates, not hidden layers.

Tanh \(\tanh(x) = \frac{e^x - e^{-x}}{e^x+e^{-x}} = 2\sigma(2x)-1\). Quotient rule gives $$\tanh'(x) = 1-\tanh^2(x)$$ Zero-centred (better than sigmoid for optimisation), derivative ≤ 1 — still saturates. Bahdanau's score function lives here.

ReLU \(\max(0,x)\). Derivative: \(\mathbb{1}[x>0]\) — exactly 1 or 0. Gradient passes untouched or dies; no shrinking. Cheap, sparse, the deep-net default. Cost: "dead ReLU" — a unit pushed permanently negative gets zero gradient forever. (At x=0 the derivative is undefined; implementations pick 0 — a subgradient. Fine to say in an exam.)

LeakyReLU \(\max(\alpha x, x),\ \alpha\approx0.01\). Derivative: 1 if x>0 else α. The trickle keeps dead units revivable.

GELU (the Transformer's choice) \( \mathrm{GELU}(x) = x\,\Phi(x)\) where Φ is the standard normal CDF — "x, kept with probability equal to how large it is". Smooth, non-monotone near 0. Common tanh approximation: $$\mathrm{GELU}(x)\approx 0.5x\left(1+\tanh\!\left[\sqrt{2/\pi}\,(x+0.044715x^3)\right]\right)$$ Exact derivative: product rule → \(\Phi(x) + x\,\phi(x)\) with \(\phi\) the normal pdf. BERT and GPT use GELU in their FFNs — say GELU, not ReLU, when asked about them.

Softmax — an activation over a vector; math + Jacobian in the theory guide §1; combined-with-loss gradient in §5 below (that combination is why you rarely need its raw Jacobian).

Worked example — feel the saturation

At x = 3: σ(3)=0.953, σ'(3)=0.953×0.047≈0.045; tanh(3)=0.995, tanh'(3)=1−0.995²≈0.010; ReLU'(3)=1. Push one gradient through 10 saturated tanh layers: ×0.01¹⁰ = 10⁻²⁰ — gone. Through 10 ReLUs on the active path: ×1. That single comparison is "why did ReLU enable deep learning" in one line.

4.1 Implement the whole catalogue (forward + backward)

import numpy as np

class Act:
    """Each activation: forward(x) stores what backward needs; backward(dout) = dout * local_grad."""

class Sigmoid(Act):
    def forward(self, x):
        self.out = 1.0 / (1.0 + np.exp(-x))
        return self.out
    def backward(self, dout):
        return dout * self.out * (1 - self.out)      # σ(1-σ), from cache

class Tanh(Act):
    def forward(self, x):
        self.out = np.tanh(x); return self.out
    def backward(self, dout):
        return dout * (1 - self.out**2)

class ReLU(Act):
    def forward(self, x):
        self.mask = x > 0
        return x * self.mask
    def backward(self, dout):
        return dout * self.mask

    def __init__(self, a=0.01): self.a = a

        self.mask = x > 0
        return np.where(self.mask, x, self.a * x)

        return 0.5*x*(1+self.t)
    def backward(self, dout):

        dt = (1 - self.t**2) * c*(1 + 3*0.044715*self.x**2)   # d(tanh(u))/dx

If sigmoid fails: you recomputed σ instead of caching (fine) or mixed up σ(1−σ). If GELU fails: the inner-derivative chain dt. This test is how you never have to *trust* your calculus — you check it.

§5 · Losses & the famous softmax + cross-entropy gradient

Motivation. The loss is the only place the training signal enters. And the most beautiful derivation in basic DL — the one interviews and exams both love — is that softmax followed by cross-entropy has the gradient \(\hat{y}-y\). Predicted minus true. Let's earn it.

Definitions

MSE (regression): \(L=\frac{1}{n}\sum_i(\hat y_i-y_i)^2\), gradient \(\frac{2}{n}(\hat y - y)\).

Cross-entropy (classification), one-hot true class c: \(L = -\log \hat y_c\) where \(\hat y = \mathrm{softmax}(z)\). Interpretation: negative log-likelihood — maximise the probability assigned to the truth. This is the LLM pretraining loss: next-token prediction = cross-entropy over the vocabulary at every position.

5.1 The derivation (do it on paper alongside)

Let \(z\) be logits, \(\hat y_j = e^{z_j}/\sum_k e^{z_k}\), \(L=-\log\hat y_c\). First expand — this step makes everything easy:

$$L = -z_c + \log\sum_k e^{z_k}$$

Differentiate w.r.t. any logit \(z_j\):

$$\frac{\partial L}{\partial z_j} = -\frac{\partial z_c}{\partial z_j} + \frac{e^{z_j}}{\sum_k e^{z_k}} = -\mathbb{1}[j{=}c] + \hat y_j$$

$$\boxed{\ \nabla_z L = \hat y - y\ }\quad (y = \text{one-hot truth})$$

No softmax Jacobian needed — the log collapsed it. This is why every framework fuses the two into one op (CrossEntropyLoss takes logits, never probabilities): fusing is both faster and numerically stabler (via the log-sum-exp trick: \(\log\sum e^{z_k} = m + \log\sum e^{z_k - m}\), \(m=\max z\)).

Worked example

Logits \(z=[2,1,0]\), true class 0. \(\hat y = [0.665, 0.245, 0.090]\) (computed in the theory guide). Loss \(=-\log 0.665 = 0.408\). Gradient \(=\hat y - y = [-0.335,\ 0.245,\ 0.090]\). Read it: push the true logit up (negative gradient), push both wrong logits down in proportion to how much probability they stole. Check: gradient sums to 0 — always true, since softmax is translation-invariant, adding a constant to all logits can't change the loss.

Drill: an LLM with vocab 50,000 predicts uniformly. Its cross-entropy loss?

\(-\log(1/50000) = \log 50000 \approx 10.82\) nats. This is why LLM training curves start near log-vocab and fall — and why "loss 3.0" means the model is effectively choosing among \(e^3\approx 20\) plausible tokens (perplexity = \(e^{loss}\)). You can now read any loss curve in any LLM paper.

§6 · A full MLP: forward and backward, derived and coded

Motivation. Backprop is not a special algorithm; it is the chain rule executed in reverse topological order with intermediate results cached. Once you derive one linear layer's three gradients, you have derived every layer of every network — attention included, since it's built from the same primitives.

6.1 The only derivation you need: one linear layer

Layer: \(Z = XW + b\), with \(X\in\mathbb{R}^{n\times d_{in}}, W\in\mathbb{R}^{d_{in}\times d_{out}}, b\in\mathbb{R}^{d_{out}}\). Given upstream gradient \(\frac{\partial L}{\partial Z} = \delta \in\mathbb{R}^{n\times d_{out}}\), we need three things:

The three gradients of a linear layer

$$\frac{\partial L}{\partial W} = X^\top \delta \qquad \frac{\partial L}{\partial b} = \sum_{\text{rows}} \delta \qquad \frac{\partial L}{\partial X} = \delta\, W^\top$$

Where these come from — scalar-level derivation for \(W\) (once in your life, do it fully): \(Z_{ij} = \sum_m X_{im}W_{mj} + b_j\), so \(\partial Z_{ij}/\partial W_{mj} = X_{im}\) and by chain rule \(\frac{\partial L}{\partial W_{mj}} = \sum_i \delta_{ij} X_{im} = (X^\top\delta)_{mj}\). ∎ The bias gradient sums over the batch because \(b\) was broadcast to every row — broadcast forward ⇒ sum backward, a rule that generalises. And a shape argument memorises the rest: \(\partial L/\partial W\) must be \((d_{in},d_{out})\) and the only way to combine \(X:(n,d_{in})\) with \(\delta:(n,d_{out})\) into that shape is \(X^\top\delta\). Shapes almost prove the formulas.

6.2 Two-layer MLP, coded exactly like the derivation

import numpy as np
rng = np.random.default_rng(0)

class Linear:
    def __init__(self, d_in, d_out):
        self.W = rng.normal(0, np.sqrt(2/d_in), (d_in, d_out))  # He init (see note)
        self.b = np.zeros(d_out)
    def forward(self, X):
        self.X = X                      # cache input — backward needs it
        return X @ self.W + self.b
    def backward(self, delta):
        self.dW = self.X.T @ delta      # (d_in, d_out)
        self.db = delta.sum(axis=0)     # broadcast fwd => sum bwd
        return delta @ self.W.T         # pass gradient to earlier layers

    net.backward(dz); net.step(0.5)

XOR is the canonical "you need the hidden layer + nonlinearity" problem (a linear model provably cannot fit it) — if this converges, your entire forward/backward stack is correct end to end.

Note: why He initialisation √(2/d_in)? (30-second version)

Var of a pre-activation \(z=\sum_m x_m w_m\) is \(d_{in}\mathrm{Var}(w)\mathrm{Var}(x)\) — same variance argument as the √d_k derivation! To keep activation variance constant layer to layer you need \(\mathrm{Var}(w)=1/d_{in}\) (Xavier, for tanh); ReLU zeroes half the variance, so compensate ×2 → \(2/d_{in}\) (He). Bad init ⇒ activations explode/vanish exponentially with depth before training even starts.

§7 · Gradient checking — how library authors trust their math

Motivation. Analytic gradients are fast but you can derive them wrong. Numerical gradients are slow but nearly impossible to get wrong. Comparing them is the professional standard — PyTorch ships torch.autograd.gradcheck doing exactly this. You built the derivation in §6; now build the auditor.

Central difference

$$\frac{\partial L}{\partial \theta_i} \approx \frac{L(\theta + h e_i) - L(\theta - h e_i)}{2h},\qquad h\approx 10^{-5}$$

Why central (not forward) difference: Taylor-expand — forward difference has error \(O(h)\); the central version's odd terms cancel, error \(O(h^2)\). Same trick, 5 orders of magnitude more accuracy for free.

def grad_check(net, X, y, param, agrad, eps=1e-5):
    """param: weight array (modified in place); agrad: your analytic gradient for it."""
    it = np.nditer(param, flags=['multi_index'])
    max_rel = 0.0
    while not it.finished:
        i = it.multi_index
        old = param[i]
        param[i] = old + eps; Lp, _ = net.loss_and_grad(net.forward(X), y)
        param[i] = old - eps; Lm, _ = net.loss_and_grad(net.forward(X), y)
        param[i] = old
        num = (Lp - Lm) / (2 * eps)
        rel = abs(num - agrad[i]) / max(1e-8, abs(num) + abs(agrad[i]))
        max_rel = max(max_rel, rel)
        it.iternext()
    return max_rel        # < 1e-6: correct. ~1e-4: suspicious. > 1e-2: a bug, certainly.

Protocol: run once on a tiny net (e.g. MLP(3,4,2), 5 samples) for every parameter tensor. Caveats worth knowing: use float64 for checking; ReLU can produce false alarms if a nudge crosses the kink at exactly 0 (jitter inputs); check before training, at random init.

Drill: your dW check passes but dX fails. Where is the bug, logically?

dW = Xᵀδ passing means δ arriving at this layer is correct and the cached X is right. dX = δWᵀ failing with the same correct δ isolates the bug to that one line — wrong transpose, or you used the updated W after a step. Gradient checking doesn't just detect bugs; run per-tensor, it localises them. That's the debugging workflow of every autograd author.

§8 · Your Value-class autograd, completed

Motivation. §6's backprop was manual: we hand-wired each backward call. An autograd engine automates this — every operation records itself into a graph, and one .backward() call replays the chain rule over the whole graph in reverse topological order. This is the exact mechanism inside PyTorch (over tensors instead of scalars). It continues your Phase-0 scaffold; __mul__ stays yours to write.

import math

class Value:
    def __init__(self, data, _children=(), _op=''):
        self.data = data
        self.grad = 0.0                    # dL/d(this node), accumulated
        self._backward = lambda: None      # how to push my grad to my parents
        self._prev = set(_children)

    def __add__(self, other):
        other = other if isinstance(other, Value) else Value(other)
        out = Value(self.data + other.data, (self, other), '+')
        def _backward():
            self.grad  += out.grad         # d(a+b)/da = 1
            other.grad += out.grad         # += not =  : a node used twice sums its grads!
        out._backward = _backward
        return out

        ...

    def tanh(self):
        t = math.tanh(self.data)
        out = Value(t, (self,), 'tanh')
        def _backward():
            self.grad += (1 - t**2) * out.grad     # §4's derivative, cached via closure
        out._backward = _backward
        return out

    def backward(self):
        # topological sort, then replay chain rule in reverse
        topo, visited = [], set()
        def build(v):
            if v not in visited:
                visited.add(v)
                for child in v._prev: build(child)
                topo.append(v)
        build(self)
        self.grad = 1.0                    # dL/dL = 1: the seed
        for v in reversed(topo):
            v._backward()

def __mul__(self, other):

Test 2 — the += trap: y = a*a with a=3 must give a.grad = 6 (both parents of the mul are the same node — with = instead of += you'd get 3, silently). Then finite-difference everything with §7's checker. Congratulations: you now hold a working, verified autograd engine — micrograd, but yours.

Cross-question: why must backward() traverse in *reverse topological* order specifically?

A node's _backward pushes gradient to its parents using out.grad, which is only final once every consumer of out has already run its own _backward. Reverse-topo guarantees all consumers precede all producers. Run in arbitrary order and nodes fire with partial grads → wrong answers that vary run to run. (Same reason PyTorch frees the graph only after backward completes.)

9.1 The canonical training loop — memorise its five beats

import torch, torch.nn as nn

class MLP(nn.Module):                          # subclass, define layers, write forward
    def __init__(self, d_in, d_h, d_out):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(d_in, d_h), nn.ReLU(), nn.Linear(d_h, d_out))
    def forward(self, x):
        return self.net(x)                     # backward comes free — you know why now

model  = MLP(2, 8, 2)
opt    = torch.optim.AdamW(model.parameters(), lr=1e-2)
lossfn = nn.CrossEntropyLoss()

X = torch.tensor([[0,0],[0,1],[1,0],[1,1]], dtype=torch.float32)
y = torch.tensor([0,1,1,0])

for step in range(2000):
    opt.zero_grad()                 # 1. clear (grads ACCUMULATE — your += design!)
    logits = model(X)               # 2. forward
    loss = lossfn(logits, y)        # 3. loss (fused log-softmax + NLL)
    loss.backward()                 # 4. your topo-sort, industrial grade
    opt.step()                      # 5. update

Forget beat 1 and gradients from every past step add up — the single most common PyTorch beginner bug, and you can explain why it exists (multi-use nodes need accumulation; PyTorch can't know when you're "done" with a grad).

9.2 Attention in PyTorch — closing the loop with the theory guide

def attention(Q, K, V, mask=None):             # identical to your NumPy, renamed
    d_k = Q.size(-1)
    scores = Q @ K.transpose(-2, -1) / d_k**0.5
    if mask is not None:
        scores = scores.masked_fill(mask, float('-inf'))
    A = torch.softmax(scores, dim=-1)
    return A @ V, A

Drill: loss.backward() errors with "grad can be implicitly created only for scalar outputs". Explain from first principles.

Your Value.backward() seeds self.grad = 1.0 — meaningful only because L is a scalar (dL/dL=1). For a non-scalar output there's no canonical seed; you'd need a whole Jacobian. PyTorch demands either a scalar loss or an explicit seed vector (y.backward(v) computes the vector-Jacobian product vᵀJ). Fix: reduce to a scalar (.mean()/.sum()) — which is why every loss ends in a reduction.
